# 开发者说明

面向想改代码、排查问题或自行构建的人。玩家请看 [玩家上手指南](玩家上手指南.md)。

---

## 1. 技术栈

- **Electron 45**，没有打包器（no bundler）。
- 主进程 / core：CommonJS。
- 渲染进程：原生 ES Modules + 手写 DOM，没有 React/Vue。
- 测试：Node.js 内置 `node --test`。
- 打包：`scripts/pack.js` 复制 Electron 运行时 + 源码，不使用 electron-builder。

没有 TypeScript、没有构建步骤。改完源码直接 `npm start` 就能看到效果。

---

## 2. 启动链路

```text
SCUM-Switcher.exe (Electron)
  └─ src/main/main.js
       ├─ app.setPath('userData', %APPDATA%\SCUM-Switcher)
       ├─ initializeConfig()
       │    ├─ loadConfig(config.json)
       │    ├─ detectScumDataDir() / detectGameRoot()
       │    └─ discoverExistingIds() + mergeDiscoveredProfiles()
       ├─ createWindow()
       │    └─ BrowserWindow(preload: src/main/preload.js)
       └─ IPC handlers
            ├─ state:get / state:refresh
            ├─ switch:start / switch:cancel
            ├─ config:update / current:set
            ├─ profile:add / update / delete / autodetect
            ├─ mods:scan / mods:setEnabled
            ├─ recovery:rollback / recovery:dismiss
            └─ ...
```

渲染进程通过 `window.api`（`preload.js` 的 `contextBridge`）调用主进程，不能直接访问 Node。

### 用户数据位置

主进程强制把 `userData` 指向 `%APPDATA%\SCUM-Switcher`，即使 `productName` 改变也不会变。这样打包版和开发版共用同一份配置。

## 3. 配置与路径

`src/core/config.js`：

- `defaultConfig()`：默认值；
- `validateConfig()`：清洗、校验、补默认值；非法 profile 会被丢弃；
- `buildPaths(config)`：把配置展开成所有实际路径；
- `discoverExistingIds(paths)`：扫描 `Saved.<id>` / `~Mods.<id>`；
- `mergeDiscoveredProfiles()`：把发现的编号加入配置（exe 为空，等用户补）。

`buildPaths` 的映射：

```js
contentDir  = <gameRoot>/SCUM/Content
paksDir     = contentDir/Paks
savedLive   = <scumDataDir>/Saved
savedProfile(id) = <scumDataDir>/Saved.<id>
savedTrash  = <scumDataDir>/.switcher-trash
modsLive    = paksDir/~Mods
modsProfile(id) = contentDir/~Mods.<id>
modsTrash   = contentDir/.switcher-trash
```

编号规则：`/^[A-Za-z0-9_-]{1,32}$/`，不区分大小写去重。创建后 UI 不允许改编号，因为目录名已经绑定。

## 4. 切换状态机

入口：`src/core/switcher.js` 的 `runSwitch()`。

### 阶段

`PHASE_RANGES` 定义了进度条区间：

| phase | 进度 | 内容 |
| --- | --- | --- |
| `precheck` | 0–3 | 检查路径、进程、目标目录、磁盘、权限 |
| `stop-game` | 3–6 | 游戏在跑时强制结束（需 `forceKillGame`） |
| `stop-launcher` | 6–13 | 关闭所有已配置的启动器，复查游戏是否被拉起 |
| `stash-saved` | 13–20 | live `Saved` → `Saved.<fromId>` |
| `load-saved` | 20–50 | `Saved.<toId>` → live（或创建空/克隆） |
| `stash-mods` | 50–55 | live `~Mods` → `~Mods.<fromId>` |
| `load-mods` | 55–95 | `~Mods.<toId>` → live（或 noMods） |
| `verify` | 95–98 | 校验文件数量/大小，或联接目标 |
| `launch` | 98–100 | 启动目标启动器 |
| `done` | 100 | 完成、写历史、清日志、清理回收区 |

### 核心动作

`stashEntry`：

```text
if live 不存在: 跳过
if live 是链接: 删除链接（数据本来就在归档目录）
if 归档目录已存在: 归档目录 → 回收区
live → 归档目录（rename）
```

`loadEntry`：

```text
if live 已存在: 报 TARGET_EXISTS
copy 模式: 复制 归档目录 → live（保留来源）
junction 模式: 创建 live → 归档目录 的目录联接
```

### 失败处理

- 预检阶段失败：还没有创建 journal，直接返回错误，不写任何文件。
- 进入切换后失败：journal 标记 `failed`，`rollbackJournal()` 按 `actions` 逆序撤销。
- 回滚成功：journal 标记 `rolledback` 并删除，写历史。
- 回滚失败：journal 保留，下次启动提示恢复。

### journal 动作类型

`journal.actions` 里每个动作都有 `seq` 和 `state`：

| kind | 数据 | 回滚 |
| --- | --- | --- |
| `trash` | `orig`, `trash` | 从回收区移回 `orig` |
| `move` | `from`, `to` | 从 `to` 移回 `from` |
| `copy` | `from`, `to` | 删除 `to` |
| `junction` | `path`, `target` | 删除链接 |
| `junction-removed` | `path`, `target` | 重建链接 |
| `mkdir` | `path` | 目录为空时删除 |

所有 `undoAction` 都先做存在性检查，因此可以对“执行到一半”的 journal 安全回滚。

## 5. 文件操作层（fsx.js）

关键函数：

- `copyDir(src, dst, { shouldAbort, onProgress, concurrency })`
  - 先扫描目录生成队列，再多 worker 复制；
  - 任一 worker 出错会设置 `workerError`，其他 worker 停止领取新任务；
  - 失败后由 journal 回滚已复制的目标目录。
- `verifyCopy(src, dst)`：对比文件数量和总大小。
- `moveToTrashSync` / `pruneTrash`
  - 回收区条目名：`<本地时间戳>-<安全标签>`；
  - `pruneTrash(trashRoot, keep)` 按名字倒序保留最新 `Math.max(2, keep)` 份；
  - 删除失败的条目会被跳过（可能被占用），不阻塞切换。
- `createJunction` / `removeJunctionSync` / `isLink` / `readLinkSync`：Windows 目录联接。
- `checkWritableSync(dir)`：实际写入探测。

> 回收区是“覆盖前旧归档”的临时保险，不是按服永久备份。按服备份是 `Saved.<id>` / `~Mods.<id>`。

## 6. 进程控制（processes.js）

### 检测

`listProcesses()` 调用 PowerShell：

```powershell
Get-CimInstance Win32_Process |
  Select-Object ProcessId, Name, ExecutablePath, CommandLine |
  ConvertTo-Json -Compress -Depth 3
```

- 用 `-EncodedCommand` 避免引号/中文转义问题；
- 强制 UTF-8 输出；
- 解析失败**抛错**（fail-closed），不会当成“没有进程”继续切换。

### 匹配

```js
normPath(profile.exePath) === normPath(proc.exePath)
&& (keyword 为空 || proc.commandLine 包含 keyword)
```

- 路径比较忽略大小写和斜杠方向；
- 关键字是完整命令行的子串匹配（包含 exe 路径本身）；
- 每个 profile 独立匹配，同一个进程可能匹配多个配置（通常不会）。

### 游戏进程

按名字 `scum.exe`、`scum-win64-shipping.exe`、`scum-win64-test.exe`，或 exe 位于游戏根目录下且名字包含 `scum-win64`。

### 关闭

`closeProcess(pid)`：

1. `taskkill /PID`（GUI 进程收到 WM_CLOSE）；
2. 等待最多 4 秒；
3. 没退出则 `taskkill /F /PID`；
4. 再等待 4 秒。

`killProcess(pid)` 直接 `/F`。

### 启动

`launchProcess()` 用 PowerShell + WMI：

```powershell
([wmiclass]'Win32_Process').Create($CommandLine, $WorkingDirectory, $startup)
```

为什么不用 Node 的 `child_process.spawn`：

- Electron 主进程可能位于 Windows Job Object（kill-on-close）；
- 在 Job 里 spawn 的子进程会随 Electron 退出一起被杀；
- WMI `Win32_Process.Create` 在 Job 外创建进程，启动器可以独立存活。

启动成功后用 `isPidAlive(pid)` 判断；如果启动器立刻退出并转交给另一个进程，会再做一次 `findProfileProcesses()` 兜底。不会像旧版那样循环扫描 40 次。

## 7. 渲染进程

- `src/renderer/index.html`：布局；
- `src/renderer/css/themes.css`：三套主题变量；
- `src/renderer/css/app.css`：布局与组件；
- `src/renderer/js/app.js`：状态、渲染、弹窗、切换流程；
- `src/renderer/js/i18n.js`：中英文扁平 key 字典。

没有框架，`el()` 辅助函数创建 DOM。所有用户可见文案都走 `t(key)`；新增文案要同时加 `zh-CN` 和 `en`。

主进程日志文案在 `src/core/messages.js`，与渲染进程的 i18n 是两套字典：core 的 key 以 `log.` / `err.` / `warn.` 为主。

### 状态刷新

- 主进程定时轮询进程（`startPolling`），有变化时 `state:detected` 推送；
- 渲染进程收到后只重绘状态相关区域；
- 切换期间 `ui.switching` 阻止重复点击。

## 8. 安全与权限

- `contextIsolation: true`、`nodeIntegration: false`；
- 渲染进程只能通过 preload 暴露的有限 API 调用主进程；
- CSP 限制为 `self`，不加载远程资源；
- 所有文件操作限制在配置路径内，MOD 启停拒绝 `..` 段和 NTFS ADS 冒号；
- 不联网、不收集数据。

### 低完整性目录

Windows 会给某些目录（例如本机的 `D:\Coding`）打的进程打 Low 完整性标签。Low 进程通常无法写入 `%LocalAppData%\SCUM`，表现为“路径有效但切换失败/无法创建目录”。

解决：

```bat
icacls "D:\AI\SCUM-Switcher" /setintegritylevel (OI)(CI)M /T /Q
```

或者把程序移到 `D:\AI`、桌面等普通目录。`pack.js` 在 Windows 上会自动尝试设置 Medium。

## 10. 打包

```bash
npm run pack -- --out "D:\AI\SCUM-Switcher" --keep 2
```

`scripts/pack.js`：

1. 检查输出目录不在源码目录内；
2. 把 `node_modules/electron/dist` 复制到临时 staging；
3. 复制 `src/` 到 `resources/app/src`；
4. 写一个精简的 `resources/app/package.json`；
5. 复制 `README.md`、`LICENSE`、图标；
6. 删除 Electron 默认的 `default_app.asar`；
7. 生成 `使用说明.txt`；
8. 把 `electron.exe` 改名为 `SCUM-Switcher.exe`；
9. 旧构建改名为 `.backup-时间戳`，按 `--keep` 清理；
10. Windows 上尝试 `icacls` 设置 Medium 完整性。

产物约 350 MB（Electron 运行时占大头）。仓库不提交该目录。

## 11. 已知限制

- 仅 Windows：依赖 `taskkill`、WMI、目录联接、`%LocalAppData%`。
- 启动器必须是 `.exe`；`.bat` / `.cmd` 请指向其最终 exe。
- 启动器识别是 exe 路径 + 可选命令行关键字；转发型启动器需要匹配实际进程。
- 地图校准是线性映射，非等距地图有偏差。
- 回收区按整个目录保留最近 N 份，不按服分别保留。
- 没有代码签名，可能触发 SmartScreen/杀软。

## 12. 修改代码时的注意事项

1. **不要绕过 journal**：任何会改变文件系统的动作都应该 `beginAction` / `finishAction`，否则失败无法回滚。
2. **预检不能写文件**：所有“询问用户”的分支必须在 journal 创建之前完成。
3. **core 不要依赖 Electron**：`src/core/*` 应能在纯 Node 下测试。
4. **新增文案要双语**：`messages.js` 和 `i18n.js` 都要加。
5. **进程检测失败要 fail-closed**：宁可阻止切换，也不要在游戏运行时替换文件。
6. **Windows 文件占用**：复制/删除可能遇到 `EPERM`/`EBUSY`，需要重试或跳过，不要直接崩溃。
7. **不要把个人绝对路径写进源码**；打包默认输出路径是维护者本机路径，其他机器用 `--out`。
