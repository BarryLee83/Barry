# SCUM 私服切换器（SCUM Server Switcher）

**中文** | [English](README.en.md)

> `English` 是同一个项目的完整英文版，不是另一个项目。

在多个 SCUM 私服之间一键切换 **存档 + MOD + 启动器**。切换前自动把当前进度保存回对应编号的目录，切换失败自动回滚；不用再手动搬 `Saved` 和 `~Mods`。

- 适用平台：Windows 10 / 11（64 位）
- 当前版本：**v1.0.2**
- 不需要安装，解压即用
- 只操作本地文件，不联网、不上传任何数据

> **第一次用请先看 [玩家上手指南](docs/玩家上手指南.md)（[English](docs/Player-Guide-EN.md)）。** 下面也写了完整的准备工作和运行逻辑。

## 它解决什么问题

SCUM 的存档和 MOD 都放在固定位置，游戏同一时间只认一套：

| 内容 | 游戏实际读取的位置 |
| --- | --- |
| 存档 | `%LocalAppData%\SCUM\Saved` |
| MOD | `<游戏目录>\SCUM\Content\Paks\~Mods` |

玩多个私服时，每个服的存档和 MOD 都不一样。手动切换容易漏文件、放错目录，甚至把另一个服的进度覆盖掉。

本工具给每个服分配一个**编号**（例如 `0509`），把每个服的数据归档到：

```text
%LocalAppData%\SCUM\Saved.0509
<游戏目录>\SCUM\Content\~Mods.0509
```

切换时：

1. 把当前 live 的 `Saved` / `~Mods` 存回**旧编号**的目录；
2. 把**新编号**的目录载入 live；
3. 启动新编号对应的启动器。

这样每个服始终有自己的完整存档和 MOD，切换只是搬运，不会互相覆盖。

## 玩家需要做的前期准备

### 1. 确认游戏和数据目录

需要两个路径：

| 名称 | 应该是 | 里面有什么 |
| --- | --- | --- |
| 游戏根目录 | 例如 `E:\SteamLibrary\steamapps\common\SCUM` | 包含 `SCUM\Content\Paks` |
| 数据目录 | `%LocalAppData%\SCUM` | 包含 `Saved` |

程序首次启动会自动探测。探测不到时，打开「设置 → 路径」手动选择。

> 游戏根目录是**包含 `SCUM` 子文件夹**的那一层，不是 `SCUM\Binaries\Win64`。

### 2. 每个服准备一个编号和一个启动器

- **编号**：只能包含字母、数字、`_`、`-`，例如 `0509`、`6646`、`server_a`。编号决定目录名，创建后不能改。
- **启动器**：该服实际使用的 `.exe`。不支持直接选 `.bat` / `.cmd`，请选它们最终启动的 exe。
- 多个服共用同一个 exe 时，才需要填「命令行关键字」；每个服的 exe 不同就留空。
- 如果这个服不用 MOD，打开「此配置不使用 MOD」。

### 3. 第一次使用前，手动备份一次

虽然程序有回收区和回滚，第一次用仍然建议手动备份。只需要做一次。

**这份备份是干什么的？** 游戏同一时间只认一份 `Saved`（存档）和一份 `~Mods`（MOD），切换器会替换它们。手动备份就是把当前这两份各复制一份到别处；程序不会读取、修改或删除这份副本。切换器自己的回收区只保留最近几份，所以这份外部备份是最后保险：选错服、切换中途失败、或以后误删归档时，可以整体复制回去。

> 下面的 `D:\SCUM-Backup\...` 只是示例，**不是程序要求的目录**。你可以换成 `E:\SCUM备份`、移动硬盘等任何有空间的位置；保留 `Saved` / `~Mods` 的文件夹名，只是为了以后能直接复制回去。

1. **完全退出游戏、官方启动器和各服的私服启动器。** 任务管理器里确认没有下面这些进程：
   - `SCUM.exe`（游戏本体，最常见）
   - `SCUM_Launcher.exe`（官方启动器）
   - `SCUM-Win64-Shipping.exe` / `SCUM-Win64-Test.exe`（其他版本/测试版游戏进程）
2. 新建备份根目录，例如 `D:\SCUM-Backup`。只建这一层，不要预先建 `Saved` / `~Mods` 子文件夹。
3. 把整个 `%LocalAppData%\SCUM\Saved` 文件夹复制到 `D:\SCUM-Backup\Saved`。
   复制完成后，备份里应直接看到 `SaveFiles`、`Config` 等文件夹，而不是 `Saved\Saved`。
4. 把整个 `<游戏目录>\SCUM\Content\Paks\~Mods` 文件夹复制到 `D:\SCUM-Backup\~Mods`。
   如果本机没有 `~Mods`，跳过这一步。
5. 如果已经按编号归档，也分别复制到备份目录：
   - `%LocalAppData%\SCUM\Saved.<编号>` → `D:\SCUM-Backup\Saved.<编号>`
   - `<游戏目录>\SCUM\Content\~Mods.<编号>` → `D:\SCUM-Backup\~Mods.<编号>`

> 注意：`Saved.<编号>` 在 `%LocalAppData%\SCUM` 下；`~Mods.<编号>` 在 `Content` 下，**不在 `Paks` 下**。这两个目录是每个服真正的长期备份，不要只备份 `Saved` 和 `~Mods`。

备份完成后再打开切换器。之后每次切换，程序都会自动保留旧版本。需要还原时：退出游戏 → 把当前 `Saved` / `~Mods` 改名加 `.bad` → 把备份复制回原位。详细步骤见 [玩家上手指南 2.4](docs/玩家上手指南.md#24-出问题怎么用这份备份还原)。

### 4. 留足磁盘空间

复制模式（默认）需要额外放一份目标存档和目标 MOD：

- 目标 MOD 有多大，就要多留差不多的空间；
- 目标存档有多大，也要多留一份；
- 再加上回收区保留的旧版本。

建议至少留 **10 GB** 空闲。空间不足时程序会在写入前提示，不会写到一半才失败。

### 5. 权限和杀毒软件

- 不要把程序放在 `D:\Coding` 这类**低完整性目录**，否则可能无法写入 `%LocalAppData%\SCUM`。推荐放在 `D:\AI\SCUM-Switcher` 或桌面。
- 程序没有代码签名，Windows SmartScreen 或杀毒软件可能提示。确认来源可信后选择「仍要运行」，或把程序目录加入信任。
- 如果启动器本身需要管理员权限，切换器也要**以管理员身份运行**，否则可能关不掉或拉不起启动器。

### 6. 每个服的数据放在哪

| 数据 | 位置 |
| --- | --- |
| 该服存档归档 | `%LocalAppData%\SCUM\Saved.<编号>` |
| 该服 MOD 归档 | `<游戏目录>\SCUM\Content\~Mods.<编号>` |
| 当前正在使用的存档 | `%LocalAppData%\SCUM\Saved` |
| 当前正在使用的 MOD | `<游戏目录>\SCUM\Content\Paks\~Mods` |

第一次添加配置时，目标目录可以不存在：

- 缺存档：切换时会询问「创建空存档」或「复制当前存档」；
- 缺 MOD：把该服的 MOD 放进 `Content\~Mods.<编号>` 后重试；确实不用 MOD 就选「不使用 MOD 继续」。

## 首次配置

### 第 1 步：确认路径

打开「设置 → 路径」，确认：

- **游戏根目录** 指向 `...\steamapps\common\SCUM`
- **数据目录** 指向 `%LocalAppData%\SCUM`

如果显示无效，点「浏览」手动选择。游戏根目录下必须存在 `SCUM\Content\Paks`。

### 第 2 步：添加服务器配置

点击左侧「添加」，填写：

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| 名称 | 显示用的名字，随便填 | `0509 服` |
| 编号 | 目录后缀，创建后不可改 | `0509` |
| 启动器程序 | 该服的 `.exe` | `D:\Games\0509\SCUM启动器.exe` |
| 启动参数 | 可选，原样传给启动器 | `-server 0509` |
| 工作目录 | 可选，留空用 exe 所在目录 | 留空 |
| 命令行关键字 | 仅当多个服共用同一个 exe 时填写 | `0509` |
| 此配置不使用 MOD | 该服没有 MOD 时打开 | 关闭 |

保存后，左侧会出现这个配置，并显示：

- `Saved.0509 存在 / 不存在`
- `~Mods.0509 存在 / 不存在`
- 启动器是否正在运行

### 第 3 步：导入已有目录

如果磁盘上已经存在 `Saved.0509`、`~Mods.0509` 这类目录，首次启动时程序会自动发现并提示导入。也可以点「添加」旁边的自动探测，或手动添加。

### 第 4 步：指定当前配置

如果程序没能从运行中的进程判断出当前是哪个服，切换前会要求你先选「当前配置」。

> 这一步很重要：程序需要知道当前 live 数据属于哪个编号，才能把它存回正确的目录。

## 日常切换

1. 完全退出游戏（切换器会检测；游戏在跑时会阻止或询问）。
2. 在左侧选中目标服务器。
3. 看中间的路线摘要：当前 → 目标、切换方式、需要的空间。
4. 点击「切换到此配置」。
5. 等待进度条走完，不要手动打开游戏或启动器。
6. 程序会自动启动目标服的启动器。

切换过程中会依次执行：

```text
检查路径/进程/磁盘
  → 关闭游戏（如允许）
  → 关闭所有已配置的启动器
  → 当前 Saved  存回 Saved.<旧编号>
  → 载入 Saved.<新编号>
  → 当前 ~Mods  存回 ~Mods.<旧编号>
  → 载入 ~Mods.<新编号>
  → 校验文件
  → 启动目标启动器
  → 记录历史
```

如果最后一步启动失败，**存档和 MOD 的切换仍然有效**，只是需要手动启动；界面会给出警告，也可以点「启动当前配置」。

## 运行逻辑：切换时到底发生了什么

假设当前在 `0509`，要切到 `6646`：

### 切换前

```text
%LocalAppData%\SCUM\
  Saved                 ← 当前 live（0509 的进度）
  Saved.0509            ← 0509 的归档
  Saved.6646            ← 6646 的归档

<游戏目录>\SCUM\Content\
  Paks\~Mods            ← 当前 live（0509 的 MOD）
  ~Mods.0509            ← 0509 的 MOD 归档
  ~Mods.6646            ← 6646 的 MOD 归档
```

### 切换后

```text
%LocalAppData%\SCUM\
  Saved                 ← 6646 的进度（从 Saved.6646 复制/联接而来）
  Saved.0509            ← 0509 的最新进度（由 live 移回）
  Saved.6646            ← 仍然保留（复制模式不会删除来源）

<游戏目录>\SCUM\Content\
  Paks\~Mods            ← 6646 的 MOD
  ~Mods.0509            ← 0509 的最新 MOD
  ~Mods.6646            ← 仍然保留
```

### 关键规则

1. **live 只有一个**：游戏只认 `Saved` 和 `Paks\~Mods`。
2. **归档按编号保存**：`Saved.<编号>`、`~Mods.<编号>` 就是每个服的“备份 + 工作副本”。
3. **切换前先存旧服**：把 live 移回旧编号目录。如果旧编号目录已经存在，旧目录会先进入回收区。
4. **复制模式保留来源**：`Saved.6646` 复制到 `Saved` 后，`Saved.6646` 还在，下次切回去还能用。
5. **联接模式不复制**：live 变成指向归档目录的目录联接，切换几乎瞬间完成。
6. **不使用 MOD 的配置**：先把当前 `~Mods` 存回旧编号，然后不创建新的 `~Mods`，游戏以无 MOD 状态启动。
7. **回收区不是每个服一份**：`.switcher-trash` 只存放“被覆盖的旧归档”，按整个回收区保留最近 N 份（默认 5，最小 2）。每个服的长期备份在 `Saved.<编号>` / `~Mods.<编号>`，不在回收区。

### 预检（写文件之前）

程序在动任何文件之前会检查：

- 游戏根目录、数据目录、`Paks` 是否存在；
- 目标启动器 exe 是否存在；
- 游戏是否正在运行；
- 目标 `Saved.<编号>` 是否存在（不存在时可创建空存档或复制当前存档）；
- 目标 `~Mods.<编号>` 是否存在（不存在时可重试或选择不使用 MOD）；
- 目标磁盘剩余空间是否足够（按同一块磁盘合并计算，额外留 200 MB 余量）；
- 数据目录、Content、Paks 是否可写。

任何一项不通过都会在写入前停止，因此可以放心点「重试」或「继续」。

### 失败与回滚

- 每个文件操作都会写入 `switch-journal.json`。
- 切换中途出错时，按相反顺序撤销已经完成的动作。
- 如果程序崩溃或被强制结束，下次启动会检测到未完成的日志，提供「回滚」或「暂时忽略」。
- 回滚失败时日志会保留，下次启动继续提示。

## 两种切换方式

在「设置 → 通用 → 切换方式」选择。

| 方式 | 行为 | 速度 | 适用 |
| --- | --- | --- | --- |
| 复制（默认，推荐） | 真实复制文件到 live | 取决于存档/MOD 大小 | 兼容性最好，绝大多数人用这个 |
| 目录联接 | live 变成指向归档目录的 junction | 几乎瞬间 | MOD 很大、经常切换；少数备份/同步工具不跟随联接 |

建议：

- 第一次用、或者不确定，选**复制**。
- 确认游戏、备份工具都正常后，再考虑联接。
- 联接模式下，`Saved` 和 `~Mods` 不是真实目录，而是链接；手动清理时不要删错目标。

## 找不到目标存档 / MOD 怎么办

### 目标存档不存在

弹窗会给出两个选择：

| 选择 | 结果 |
| --- | --- |
| 创建空存档 | 新建空的 `Saved.<编号>`，进游戏后重新建角色 |
| 复制当前存档 | 把当前 `Saved` 复制一份作为该服的起点 |
| 返回 | 不切换 |

### 目标 MOD 目录不存在

1. 打开 `Content` 目录；
2. 新建 `~Mods.<编号>`，把该服的 MOD 放进去；
3. 回到弹窗点「重试」。

如果这个服确实不用 MOD，点「不使用 MOD 继续」。程序会清空当前 live MOD（存回旧编号），以无 MOD 状态启动。

### 游戏正在运行

默认「先询问我」。可以选：

- 关闭游戏后重试；
- 强制关闭游戏并继续。

也可以在「设置 → 安全」改成「自动强制关闭」。**切换前必须关闭游戏，否则存档可能损坏。**

## 启动器识别与命令行关键字

程序判断“某个服的启动器是否在运行”的规则：

1. 进程的 exe 路径必须和配置里的**启动器程序**一致（忽略大小写、斜杠方向）；
2. 如果填了「命令行关键字」，进程的完整命令行还必须包含这个关键字（忽略大小写）。

关键字匹配的是**完整命令行**，包括 exe 路径本身。因此：

- 每个服 exe 不同：关键字留空。
- 多个服共用一个 exe，靠参数区分：填参数里稳定出现的文本，例如 `-server 0509` 或 `0509`。
- 如果启动器只是转发参数给另一个进程：把关键字填成**实际游戏进程命令行**里出现的文本，或者直接把启动器路径指向实际进程。
- 关键字填错不会影响切换文件，但会导致“关不掉旧启动器”或“识别不到正在运行的服”。

v1.0.2 起，启动成功后用 PID 判断是否存活，不再反复扫描进程列表，所以不会再因为关键字不匹配而卡 45 秒。

## 安全机制

| 机制 | 作用 |
| --- | --- |
| 预检先行 | 缺文件、游戏在跑、空间不足等问题在写入前发现 |
| 操作日志 | 每个动作写入 `switch-journal.json`，失败可按相反顺序回滚 |
| 崩溃恢复 | 中途退出后，下次启动提示回滚或忽略 |
| 回收区 | 被覆盖的旧归档移入 `.switcher-trash`，不直接删除 |
| 切换后校验 | 对比目标与 live 的文件数量和总大小（可关闭） |
| 历史记录 | `history.json` 记录路线、方式、耗时、结果 |
| 不联网 | 没有遥测、没有上传；只读写本地文件 |

注意：

- 回收区按“最近 N 份”清理，**不是每个服永久保留**。长期备份请依赖 `Saved.<编号>` / `~Mods.<编号>`，或者自己额外备份。
- 「删除配置」只从列表中移除，不会删除磁盘上的 `Saved.<编号>` / `~Mods.<编号>`。
- 程序不会修改游戏安装内容，只移动/复制存档和 MOD 目录。

## 附加工具

左侧下方的三个工具不是切换的必需步骤，但常用。

### 管理员指令

- 内置常用 `#` 指令速查，按分类浏览、搜索、一键复制。
- 支持添加自己的指令，保存在 `%APPDATA%\SCUM-Switcher\admin-custom.json`。
- 不同服务器/插件版本可能略有差异，以游戏内 `#` 列表为准。

### 地图与坐标

- 导入 PNG / JPG / WEBP 地图（可截图游戏内 M 键地图）。
- 用两个已知点校准像素 ↔ 世界坐标。
- 点击地图取点，复制 `#Teleport X Y Z`。
- 支持保存自定义点位。
- 校准是线性映射，适用于等距投影的官方地图；非等距自制地图会有偏差。

### MOD 检查

- 统计当前 live `~Mods` 的文件数、总大小、各顶层条目占用。
- 发现同名 `.pak` 冲突（不同子目录下同名文件）。
- 按条目停用/启用：
  - 停用只是移动到 `Paks\~Mods.disabled`，**不会删除**；
  - `.pak` 的 `.sig` 会一起移动；
  - 重新启用时一起恢复。

## 常见问题

### 切换很慢

- 复制模式要真实复制存档和 MOD，第一次或 MOD 很大时慢是正常的。
- 机械硬盘、杀毒软件实时扫描会明显拖慢。
- 联接模式几乎瞬间完成。
- v1.0.2 已修复“启动器关键字不匹配导致每次多等约 45 秒”的问题；如果仍慢，看日志里哪一步耗时最长。

### 切换后游戏没有启动

- 检查配置里的启动器 exe 是否存在、是否需要管理员权限。
- 检查「启动参数」和「工作目录」。
- 看界面警告和 `%APPDATA%\SCUM-Switcher\logs`。
- 存档和 MOD 已经切换成功，可以点「启动当前配置」手动启动。

### 旧启动器没有被关闭

- 确认 exe 路径和实际运行的完全一致。
- 多个服共用一个 exe 时，确认「命令行关键字」确实出现在进程命令行里。
- 启动器可能需要管理员权限；以管理员身份运行切换器。
- 也可以手动关闭后重试。

### 提示“目标 MOD 目录不存在”

- 在 `Content` 下新建 `~Mods.<编号>`，放入该服 MOD，再点「重试」。
- 如果该服不用 MOD，打开配置里的「此配置不使用 MOD」，或弹窗选「不使用 MOD 继续」。

### 回收区里为什么没有某个服的备份

回收区按整个目录保留最近 N 份，不是每个服各一份。每个服的长期数据在 `Saved.<编号>` / `~Mods.<编号>`，这两个目录才是真正的按服备份。回收区只是“覆盖前的旧版本”临时保险。

### 提示没有权限 / 无法写入存档

- 把程序移到普通目录（例如 `D:\AI`），不要放在 `D:\Coding` 等低完整性目录。
- 必要时以管理员身份运行。
- 检查 `%LocalAppData%\SCUM` 和游戏 `Content` 目录的写入权限。

### 杀毒软件报毒 / SmartScreen 拦截

程序未签名，可能被误报。确认来源可信后：

- SmartScreen：更多信息 → 仍要运行；
- 杀毒软件：把程序目录加入信任；
- 或者从源码运行/自行构建。

### 游戏更新后 MOD 不见了

Steam 验证游戏完整性可能重置 `Paks\~Mods`。切换器的归档 `~Mods.<编号>` 不受影响；重新切换一次即可载入。更新前建议先切到“不使用 MOD”的配置，或手动备份。

### 能不能直接选 Steam？

程序启动的是 `.exe`，不是 Steam 链接。如果该服通过 Steam 启动，请把启动器指向实际 exe（例如 `SCUM\Binaries\Win64\SCUM.exe`），或使用该服提供的启动器。直接启动 exe 可能没有 Steam 覆盖层，按需选择。

### 删除配置会删存档吗？

不会。只从列表移除，磁盘上的 `Saved.<编号>` / `~Mods.<编号>` 保留，之后可以重新添加同编号配置导入。

### 怎么卸载？

1. 关闭程序；
2. 删除程序目录；
3. 可选：删除 `%APPDATA%\SCUM-Switcher`（配置、日志、历史）；
4. 游戏存档和 `Saved.<编号>` / `~Mods.<编号>` 不会被删除，需要的话自行清理。

要求：

- Windows 10 / 11 x64
- Node.js 22 LTS 或更新
- npm

```bash
npm install
npm test
npm start
```

`npm start` 直接以开发模式启动 Electron。

### 生成免安装版

```bash
npm run pack -- --out "D:\AI\SCUM-Switcher" --keep 2
```

- `--out`：输出目录，必须在源码目录之外；
- `--keep`：保留最近几份旧构建备份，最小 2；
- 脚本会复制 Electron 运行时、应用源码、图标和说明文件；
- 在 Windows 上会尝试把输出目录完整性级别设为 Medium。

默认输出目录是 `D:\AI\SCUM-Switcher`（维护者本机路径）。其他机器请显式传 `--out`。

> **不要从 `D:\Coding` 这类低完整性目录运行打包后的 exe。** 这类目录下的进程可能无法写入 `%LocalAppData%\SCUM`。发布版应放在 `D:\AI`、桌面等普通目录；必要时执行：
>
> ```bat
> icacls "D:\AI\SCUM-Switcher" /setintegritylevel (OI)(CI)M /T /Q
> ```

### 测试

```bash
npm test
```

当前 28 个核心测试，覆盖文件复制/回滚、配置校验、MOD 启停、切换状态机、缺失目标、联接模式、进程匹配等。
